# 软件验证与已知限制

本项目在 Windows 11 x64、Python 3.13.3 上开发验证。v0.2.0 增加 GT-M601 蓝牙套件的配套 USB 接收器/CH340 串口温度通道；脑环、指夹及温度三路的实物联调状态明确为 **待验收**。

自动化测试覆盖脑电符号极值和通道顺序、PPG 分帧及损坏输入、BLE 命令和异常清理、串口拔出、3 秒门禁、六个缩短阶段、评分、掉线重做、失败对照排除、数据保存边界和去重、延迟回调、队列溢出、写盘失败和窗口操作。温度回归范围包括严格 ASCII 帧及分片/多帧、异常报文、串口参数、低频准备与过期状态、可选启用、测量配置、温度数据与原始记录、阶段边界、重做和质量阈值。模拟数据通过设备协议解析、共同控制器、后台写入器进入 CSV；缩短阶段用于软件验证，不代表已完成真实的 18 分钟实验。

源码 GUI 和打包后 EXE 均需走完模拟自检，生成六阶段三路文件、评分、事件和完成汇总后才能发布。自检使用六个 2 秒阶段及 1 Hz 模拟温度；真实温度设备的固定上报周期未由手册承诺。最终测试数量和打包结果以本次实际测试报告为准，本文件不把待执行的检查记作通过。

含温度功能的 v0.2.0 通过 [GitHub Release](https://github.com/yangr8640-eng/mist-eeg-ppg/releases/tag/v0.2.0) 以预发布（Pre-release）提供；[Windows 运行包下载](https://github.com/yangr8640-eng/mist-eeg-ppg/releases/download/v0.2.0/MIST-EEG-PPG-Windows-x64.zip)。开发电脑仍可使用 `dist/MIST-EEG-PPG/MIST-EEG-PPG.exe` 或指向它的现有快捷方式。旧 v0.1.0 下载包不含温度功能，发布运行包也不代表完成真实硬件验收。

2026-09-20 v0.2.0 软件验证结果：自动化测试 **99 项通过**；源码模拟自检约 21.9 秒，打包 EXE 模拟自检约 21.8 秒并报告 `passed`。EXE 自检生成六阶段 × 三路共 18 个非空 CSV，每阶段含 2 个模拟温度点，记录 3 次答题和 6 次评分。上述结果只证明本次构建的软件检查通过，真实硬件验收仍未完成。

本机 Windows BLE 扫描和串口枚举可以运行；设备缺席时不将其标记为连接成功。模拟数据保存在 `SIMULATED` 子目录，不作为真实实验数据。

尚待实际设备验证：

- 脑环固件是否使用已静态核对的 FE40/FE41/FE42 服务、100 字节通知和 500 Hz 输出。
- µV 换算、通道顺序、电极脱落状态与原厂软件/实际佩戴的对应关系。
- 指夹板卡上的固件是否确为 RED 整数流、57600 波特率，以及其真实输出频率。
- GT-M601 蓝牙套件能否通过配套 USB 接收器的 CH340 COM 端口稳定输出 115200 baud、8N1、`A+XX.XB\r\n` 帧，出厂配对及恢复配对是否正常。
- 温度真实上报间隔是否满足当前软件的连续 3 秒、相邻有效更新间隔小于 1.5 秒准备策略，以及蓝牙中断但 COM 端口保留时能否按 3 秒无数据规则中断阶段。
- 实际测量部位、固定方式、接触及热平衡对温度的影响，与参考温度计的差异；当前记录为接触部位表面温度，未验证为核心体温。
- 长时间实际采集中的蓝牙丢失、串口间断、休眠和电源管理影响。
- 设备采样到主机接收的延迟，以及实际屏幕/声音呈现延迟。需要专用测试方法时按 [验收步骤](HARDWARE_ACCEPTANCE.md) 处理，不能用接收抖动冒充同步误差。

温度质量报告采用 3 秒接收间隔阈值，EEG/PPG 保留 100 毫秒指标；约 1 秒更新不会被误计为温度长间隔，间隔统计也不表示精确丢包数。所有启用通道都按同一主机接收时间切段，尚无设备时间戳、设备计数或共同硬件触发。

断电或强制结束程序时可能留下 `in_progress`/`recording` 状态以及最后一次刷新后尚未写入的数据；这些文件不能当成完成的阶段。可读的原始文件保留，程序不会覆盖同一尝试。当前不支持跨进程自动续做中断会话，应新建会话。
