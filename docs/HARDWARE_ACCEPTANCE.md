# 到实验室后的实物验收

脑环、指夹和 GT-M601 蓝牙温度套件尚未完成三路真实设备联调。软件解码、状态机、模拟采集和 GUI 验证不能替代实际佩戴与传输验证，自动生成的 `hardware_acceptance: not_verified` 如实保留这一状态。本清单用于之后的首次验收，不表示本次已经完成实物验证。

## 1. 记录测试环境

使用测试编号（例如 `LAB_CHECK_001`），避免使用正式被试信息。记录：程序版本、Windows 版本、电脑型号、蓝牙适配器、脑环型号和可见固件版本、Arduino 型号及当前草图版本、GT-M601 模块与配套 USB 蓝牙接收器、CH340 驱动版本和 COM 端口、温度测量部位及固定方式、测试日期、操作员、保存目录。确认使用含温度功能的 [v0.2.0](https://github.com/yangr8640-eng/mist-eeg-ppg/releases/tag/v0.2.0)，旧 v0.1.0 包不能用于三路验收。

先关闭 QtBLE、Arduino 串口监视器、独立 PPG 和厂家温度采集程序。确认脑环和温度模块有电、电脑蓝牙打开，Arduino 和配套温度 USB 蓝牙接收器已连接。温度通过接收器的 CH340 串口接入；若出厂配对丢失，先用厂家工具恢复配对，再退出厂家工具释放串口。测试数据留在本地，不上传含真实被试信息的文件。

## 2. 连接与波形

- 关闭模拟模式，扫描并选择实际 `QX-EEG-4`；如名称不同，核对设备身份后再连接。
- 指夹选择正确 COM 端口。当前支持 57600 baud、每行一个 RED 整数的 Example-3 文本固件。
- 默认启用温度，选择其独立 COM 端口；应为 115200 baud、8N1，报文为严格 ASCII `A+XX.XB\r\n`（允许负号）。故意选择与指夹相同的 COM 端口时，程序应阻止冲突连接。
- 三设备均应连续输出有效数据至少 3 秒，程序才允许填写被试信息。温度有效更新间隔须小于 1.5 秒；这是当前软件准备策略，厂家未承诺固定周期，若真实输出不满足该策略，应先调查实际周期和研究要求。
- 查看脑电四通道和 PPG 预览，确认实际动作/接触变化能改变波形。不能将单纯蓝牙已连接或 COM 端口存在视为通过。
- 脑环标称每通道 500 Hz，通常每 16 ms 收到一个 100 字节通知。若持续报长度错误，记录原始通知长度及系统信息，暂不正式使用；不能忽略错误强行拼包。
- PPG 当前草图含 `delay(8)`，输出约不超过 125 Hz，实际还受计算与传输影响。记录实际速率，不能要求它与 EEG 都显示 500 Hz。
- 电量原始数值仅留作诊断，不是校准百分比。检查取下/恢复电极时整体脱落状态是否随之变化。
- 检查温度摄氏数值、绝对温度趋势、有效接收率、距上次有效更新的时间及已存数量。按安全的温和接触变化观察温度随时间变化，不能把曲线变化本身当成测量精度校准。
- 启用温度但未填写测量部位时，不应创建会话；填写实际部位后再继续。三秒数据流就绪不代表传感器已达热平衡。
- 单独新建一次禁用温度的会话，确认只要求脑环和指夹就绪，清单只含两路且阶段目录无温度文件。

## 3. 短流程预演

把六阶段时长临时设置为 10–20 秒，创建测试会话并完成全部阶段和 VAS。检查算术可输入负数、Enter 提交有效、压力任务显示倒计时、闭眼阶段结束有提示音、阶段结束自动保存、下一阶段不会覆盖上一阶段。

结束后确认：

- `session.json` 状态为 `completed`；六个阶段目录齐全，且每个 `stage.json` 状态为 `completed`。
- 每个阶段 EEG/PPG/温度 CSV 有有效数据，原始 JSONL 存在；`trials.csv`、`ratings.csv`、`events.jsonl` 可读取。
- 评分有六条。阶段到时尚未完成的题目是 `stage_truncated`，不算普通答错。
- CSV 的 `received_ns` 都落在相应 `[start_ns, end_ns)` 范围。
- EEG 每个有效通知对应 8 行，`sample_in_packet` 为 0–7；同一设备同一阶段不存在重复的 `(host_sequence, sample_in_packet)`。
- 温度 CSV 的 `temperature_c` 与原始帧对应，`timing_basis` 为 `host_receive`；`session.json` 的 `enabled_devices` 包含 `temperature`，`temperature.config` 与所选串口和实际测量部位一致，测量含义为接触部位表面温度。
- 温度质量的 `receive_gap_threshold_seconds` 为 3 秒，约 1 秒更新未计作长间隔；检查实际样本数量而非套用 EEG/PPG 的速率要求。

## 4. 断线与重做

用测试会话分别测试指夹 USB 拔出、脑环关机/断开、温度 USB 蓝牙接收器拔出，以及接收器保持插入但温度模块关闭或蓝牙链路中断。最后一种情况 COM 端口可能仍然存在，应根据有效数据是否过期判断。不应在正式被试身上以拔线方式测试。

当前阶段应立即或在无有效数据 3 秒后停止，显示未完成并保留文件。恢复连接且有效流稳定后，重做当前阶段，确认生成 `attempt_02`，先前 `attempt_01` 文件未覆盖。中断对照任务后重做，压力阶段只采用成功对照尝试的反应时和正确率。

温度断流后，界面应说明最后数值已过期及更新年龄，不能持续把旧值显示为新数据。确认重做后的温度已存数量从零开始；失败尝试仍能读取其温度 CSV、原始记录和停止原因。

另做一次阶段中按 Esc 主动结束的测试：确认阶段状态为 `incomplete`，会话为 `aborted`，已采文件可以读取。

## 5. 连续 3 分钟与量程核验

至少采一个完整 180 秒阶段，然后做一次默认六阶段完整预演。记录每阶段的有效采样数、有效接收率、最长接收间隔和解析错误数。

EEG 理想 180 秒约 90,000 行，每行包含四通道；由于按整包接收时间切段，边界可能相差一包，不能仅凭恰好等于 90,000 判定同步通过。PPG 和温度按其实际流速判断，保留速率波动事实；温度手册没有固定频率承诺，不要求真实 180 秒必须恰好有 180 个样本。持续明显偏离已确认的正常速率、出现解析错误、长间隔或丢失阶段文件都需先调查。

分别使用原厂软件和本程序进行对比采集，不同时争抢同一设备。核对四通道顺序、波形极性、量程、整体电极状态。两次独立采集不能证明逐点一致；若有共同已知信号源，再做可量化对比。记录尚未确认的电极位置和硬件版本差异。

温度在稳定环境和接触条件下与合适的参考温度计对比，记录部位、环境、固定方式、热平衡等待时间、参考值及偏差。可另用厂家上位机核对格式和单位，但不能同时占用同一串口。厂家器件精度参数、芯片内部分辨率和程序保存的小数位数都不等于已验证的人体测温误差。皮肤接触温度不能直接作为核心体温。

## 6. 同步验收的边界

当前程序按共同主机接收时间对齐。EEG 包内时间按 500 Hz 回推；PPG 和温度保存完整报文到达时刻。三设备都没有可用的设备时间戳或计数器，蓝牙与串口延迟未标定，温度感温响应及接触热平衡还会引入测量响应时间。质量报告中的接收抖动不是跨设备真实同步误差。

如果研究只需要这种软件对齐，记录接受的限制；若必须知道实际 EEG/PPG/温度采样误差，应安排相关设备可见的外部同步信号/专门硬件，测量误差和漂移。显示刺激的真实上屏时间、闭眼提示音的实际声学开始也未由光电或声学传感器测量。

验收结论记录为：通过项目、失败项目、尚未核实项目、对应会话路径、操作员和日期。不要仅因一次模拟自检通过就把硬件标为通过。

## 开发者软件自检（无需设备）

以下命令强制使用模拟设备，不扫描或访问真实硬件。它通过真实 Qt 绘制完成六个 2 秒阶段、三路采集、作答、评分和保存；模拟温度按 1 Hz 更新，2 秒窗口用于覆盖低频数据。此命令用于软件回归，不属于被试实验操作。

```powershell
python -m mist_app --self-test C:\Temp\mist-check --self-test-hidden
```

打包 EXE 可使用同样参数。检查输出目录的 `self_test_report.json` 是否通过，并检查 `01_setup.png`、`02_question.png`、`03_completed.png`。模拟会话仍在 `SIMULATED` 目录中，不能当作实物验收记录。
