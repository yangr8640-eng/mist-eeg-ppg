# 设备协议与时间基准

本项目独立实现设备通信和实验规则。以下脑电协议来自用户提供的软件的静态检查，并通过 Android 与 Windows 两份实现交叉确认；不是厂家发布的正式协议文档。项目不分发这些厂商二进制文件。实物采集验收仍需完成。

## QX-EEG-4 脑环

| 项目 | 值 |
| --- | --- |
| 广播设备名 | `QX-EEG-4` |
| 服务 | `0000fe40-8e22-4541-9d4c-21edae82ed19` |
| 写入特征 | `0000fe41-8e22-4541-9d4c-21edae82ed19` |
| 通知特征 | `0000fe42-8e22-4541-9d4c-21edae82ed19` |
| 启动 / 停止 | 一个字节 `0x31` / `0x32`，即 ASCII `1` / `2` |
| 标称采样率 | 每通道 500 Hz |
| 每个通知 | 100 字节，8 个采样时刻，每时刻 4 通道 |
| 包头 | 字节 0、1 为 `FF FD` |
| 电极状态 | 字节 2；非零表示整体电极脱落 |
| 电池原始值 | 字节 3；未经校准，不显示为可靠百分比 |
| 波形载荷 | 字节 4–99，8 行 × 4 通道 × 3 字节 |
| 校验 / 设备序号 / 设备时间 | 数据帧均未包含 |

采样点 `i`（0–7）、通道 `c`（0–3）位于 `4 + 12*i + 3*c`，占 3 字节；大端、有符号 24 位二补码。四个通道依次为 CH1、CH2、CH3、CH4；电极的实际头皮位置未由软件资料确认。

厂商转换为微伏的系数为：

```text
µV = signed24 × 1.2 / 8388608 / 8 / 6 × 1000000
   = signed24 × 0.0029802322387695312
```

保留未滤波原始计数，避免显示滤波影响研究数据。微伏换算须在实物验收时与原厂软件的原始波形比较。

严格按完整的 100 字节通知解码，要求 BLE ATT MTU 至少容纳 100 字节特征值（MTU ≥ 103）。厂商通知回调同样直接将一整个通知送入解码器，没有软件分片组装。未知长度、错误包头的通知属于协议异常；不能靠寻找载荷中偶然出现的 `FF FD` 猜测分帧，也不能当作零值正常采样。

没有设备序号，因而主机不能可靠区分全部丢包、重复包及延迟。接收间隔异常与有效接收速率只能作为质量提示，不能证明精确丢包数。

厂家电池公式在两份实现中均为 `clamp(int((raw * 0.02148 - 3.65) * 2), 0, 100)`；对单字节原始值只能产生非常窄的结果范围，因此本项目保留 `battery_raw`，不把该结果宣称为校准电量。

## 指夹 PPG

本项目沿用用户的 `arduino_red_ppg_collector.py` 所采用的 Example-3 文本协议：57600 baud，从 Arduino 接收每行一个有符号十进制 RED 原始值，允许 CRLF 或 LF。具体串口由操作员选择。增量解码保留半行并在后续读取完成；多个完整整数行可包含在同一次读取中。启动说明行、无效整数、超长行属于诊断或解析异常，不当作生理采样。波形数据必须通过协议解析且持续更新，单纯出现 COM 端口不等于采集就绪。

本地 `AFE4490_library` 的 Example-3 草图每轮 `Serial.println(RED_data)` 后执行 `delay(8)`。因此主机输出率大约不超过 125 Hz，并受到 SPI 读取、计算和串口时间影响；不能因为 AFE 内部转换配置可能是 500 Hz，就把收到的文本流视为 500 Hz。程序测量实际有效接收速率，不修改固件，也不支持 Example-1 的二进制帧作为此文本输入。

该文本协议没有设备时间戳或计数。本项目为 PPG 保存读到完整行时的主机接收时刻，不伪造固定间隔采样时间；同一次读取中多行共享接收时刻。需要更准确的采样时刻时，应升级 Arduino 固件输出设备计数/采样时钟，并为时钟映射另行验证。

## 时间、阶段边界与质量

EEG、PPG 和实验事件共同使用同一进程的单调主时钟；启动时记录该时钟与 UTC 的对应锚点。单调时间用于间隔及阶段控制，UTC 用于定位实验日期，不以系统墙上时钟差计算反应时。

必须区分三个概念：

- **接收时刻**：主机实际收到整包数据的单调时刻，可直接观测。
- **估计采样时刻**：根据标称频率、包内顺序及接收时刻推算，不是设备硬件时间戳。
- **实验事件时刻**：程序记录刺激、作答、阶段等事件的时刻；GUI 提交绘制不等于显示器真实发光时刻。

蓝牙缓冲、串口缓冲、操作系统调度和显示刷新都会引入未知延迟。软件使用共同时间轴并报告接收质量，但没有共同硬件触发、光电传感器或设备时间戳，因此不能宣称达到已验证的毫秒级生理同步。不要将 EEG 500 Hz 和 PPG 采样率直接改为相同值以假装对齐；分析时根据保存的时间字段重采样，保留各自原始速率。

连接预览用于确认有效流。实验阶段之间设备可以保持连接和预览，但每个阶段独立打开、停止及封存记录，说明页和评分不自动混入阶段生理数据。阶段截止以共同单调时钟判断，未完成题记作截断，不能误算普通答错。

记录窗口明确为 `start_ns <= received_ns < end_ns`，即按整包/整次读取的主机接收时刻切段。EEG 包内第 `i` 点的估计时间为 `received_ns - (7-i)*2000000` 纳秒；包内末点锚定接收时刻，未补偿蓝牙传输延迟。靠近阶段开始的包，早期点的估计阶段时间可能小于零，这是边界与包内回推的真实结果，应保留并在分析中按需要裁剪。`host_sequence` 只是主机接收记录编号，不能用它推断设备端丢包。

CSV 的 `received_ns`、`session_seconds`、`stage_seconds` 都基于接收时刻。EEG 另含 `estimated_sample_ns`、`estimated_stage_seconds`、`timing_basis`，以及 `ch1_raw`–`ch4_raw`、`ch1_uv`–`ch4_uv`、电极及电池原始值；PPG 的生理值列为 `red`。原始 JSONL 留存 `raw_hex`、接收时间、解析错误和元数据。单调时钟与 UTC 的对应信息保存在 `session.json` 和阶段元数据中。

任一设备连续 3 秒没有有效数据，或出现明确断开/采集错误，当前阶段应以不完整状态保存，停止正式任务并要求恢复连接后重做该阶段。重做生成新的尝试记录，保留失败记录。出现异常的对照阶段不能用于压力阶段校准。

## 实物验收清单

静态解码测试和模拟实验不能替代实物验收。正式使用前应完成：

1. 连接真实脑环和指夹，确认设备身份、有效帧长度、通道顺序、频率设置及连续接收速率。
2. 对比原厂软件的 EEG 原始值/微伏量程及电极脱落状态；保留对比记录。
3. 连续采集至少一个完整 3 分钟阶段，对照数据行数、实际持续时间、间隔异常和保存结果。
4. 分别断开两种设备，验证中断阶段标记、文件保留及重新执行阶段。
5. 检查全部六阶段、VAS、行为和事件文件，确认 UTC 锚点、接收时刻及估计采样时刻可以解释。
6. 若研究需要量化同步误差，使用双方可见的外部信号或专门同步硬件进行测量，记录误差分布；未经测量不得将软件时间字段当作硬件精度证明。
